# 腾讯新闻搭子 (Tencent News Buddy)

> 让每一条新闻都与你相关

CodeBuddy / OpenClaw Skill，通过 AI 大模型 + 实时联网搜索，为用户提供高度个性化的新闻推荐与深度解读。

## 核心特性

- **隐式画像引擎** — 安装后主动收集用户信息，自动构建脱敏画像，用户零配置
- **带权重 + 情感标注的兴趣系统** — 每个兴趣带 `{tag, weight, added_at, sentiment}` 四维结构，支持 positive/skeptical 两种情感态度，skeptical 的兴趣自动从搜索维度中排除但保留在画像中
- **30天半衰期时间衰减** — 长期不提及的兴趣自动降权直至清理，频繁关注的领域权重更高（上限2.0）
- **近义词智能合并** — 词根级别匹配，"Rust编程"和"Rust语言"自动识别为同一兴趣并提权
- **三向画像操作** — add（添加/提权）、remove（移除）、skeptical（标记怀疑态度降权不删除）
- **AI 自由文本备忘 (notes)** — 500字符上限，AI可写入正则无法覆盖的用户偏好观察（参考 Hermes Agent 的 USER.md 设计理念）
- **定时兴趣合并建议** — 每日更新时自动检测低权重相似兴趣对，输出合并建议供 AI 执行
- **每次调用自动刷新画像** — 不仅在晚12点定时更新，每次推送前都会执行衰减和刷新
- **安装即创建定时任务** — 安装后直接创建两个定时任务（早9点推送 + 晚12点画像更新），零额外交互
- **SCQA 个性化改写** — 同一条新闻，不同画像看到完全不同的标题、摘要和行动建议
- **实时联网搜索** — 每次推送都是 web_search 实时搜索，不是 RSS 缓存
- **隐私安全** — 所有数据仅存本地，隐私信息在存储前语义级脱敏

## 工作流程

```
安装 skill
    ↓
主动打招呼 → 收集用户信息 → 构建初始画像 → 直接创建两个定时任务
    ↓
每天早上 9 点（自动）：
    画像衰减刷新 → web_search 多维搜索 → 评分筛选 → SCQA 个性化改写 → 推送
    ↓
用户随时对话：展开某条 / 换一批 / 聊新闻
    ↓
每天晚上 12 点（自动）：
    兴趣衰减 → 合并建议 → 消费维度 boost → 搜索维度重推 → 过期数据清理
```

## 快速开始

安装到 CodeBuddy 的 skills 目录后，AI 会自动：

1. 向你打招呼，询问职业、城市、兴趣
2. 构建个性化画像
3. 直接创建两个定时任务，创建完成后告知你

之后每天早上自动收到个性化新闻。也可以随时对话：

```
展开第 3 条          → 深度解读
换一批              → 重新搜索
最近在看 Rust       → 静默更新画像（positive），下次推送自动加入
Rust太难了放弃了     → 静默标记 skeptical，暂停推送但保留画像
区块链不用推了       → 静默移除，永久不再推送
```

## 画像引擎

| 能力 | 说明 |
|------|------|
| 三层脱敏 | 年龄→人生阶段，城市→城市层级，职业→行业背景 |
| 兴趣提取 | 42个正则模式覆盖19种硬核兴趣+15种轻松兴趣+8种避险动机 |
| 模板匹配 | 8种典型人群画像模板，关键词命中≥2时自动补全兴趣 |
| 权重机制 | 用户直接提取=1.0，模板补充=0.7，对话boost=+0.3，日度boost=+0.15 |
| 时间衰减 | 半衰期30天，权重<0.15自动清理，每类别上限12个 |
| 情感标注 | positive（正常推荐）/ skeptical（暂停推荐但保留画像） |
| 近义词合并 | 词根级别匹配，"AI与大模型"和"大模型技术"自动识别为同一兴趣 |
| AI自由备忘 | notes字段（500字符，§分隔），记录正则无法覆盖的用户偏好 |
| 搜索维度推断 | 画像变化自动重推5-8个搜索维度，统一去重 |
| 三级信号检测 | 高置信度（立即更新）/ 中置信度（观察2轮）/ 低置信度（skeptical或remove） |
| 每日兴趣合并 | 自动检测低权重相似兴趣对，输出合并建议 |

## 文件结构

```
news-buddy-skill/
├── SKILL.md                   # AI 执行指南（Prompt 编排）
├── package.json               # v3.1.0
├── config.cjs                 # 配置管理（预留扩展）
├── data/
│   └── profile-templates.json # 8种画像模板
├── scripts/
│   └── news-buddy.cjs         # 核心脚本（11个CLI命令）
└── .cache/                    # 本地缓存（git忽略）
    ├── profile.json           # 用户画像（带权重+时间戳+sentiment+notes）
    ├── news.json              # 新闻存档（7天自动清理）
    ├── shown.json             # 已展示记录（3天自动清理）
    └── history/               # 按日期归档（7天自动清理）
```

## CLI 命令

```bash
--get-profile                  # 查看画像
--init-profile --input "..."   # 初始化画像（已有时合并保留）
--daily-update                 # 画像刷新（衰减+合并建议+boost，每次推送前+定时任务调用）
--update-profile --add '{...}' # 添加/移除/skeptical 兴趣，或写入 notes
--save-news --data '{...}'     # 保存新闻
--get-shown-news               # 获取已展示列表
--mark-shown --titles '[...]'  # 标记已展示
--get-history [date]           # 查看历史
--debug-profile                # 调试画像
--reset-profile                # 重置画像
```

## 技术栈

- **零外部依赖** — `dependencies: {}`，纯 Node.js 原生 `fs` + `path`
- **零模型训练** — 全部 Prompt 工程 + 规则引擎
- **零服务器** — 不需要 API Key、数据库、后端服务
- **双层架构** — AI 负责智能（搜索/理解/改写），脚本负责确定性（脱敏/存储/衰减/推断）

## 设计参考

本项目在画像系统设计中参考了以下开源项目的重要思路：

- **[Hermes Agent](https://github.com/NousResearch/hermes-agent)** (Nous Research) — 参考了其"冻结快照"记忆模式（会话开始时加载一次画像）、USER.md 自由文本用户建模（对应本项目的 `notes` 字段）、以及 `add/replace/remove` 三操作的记忆管理范式。Hermes 的 [Honcho](https://github.com/plastic-labs/honcho) 辩证用户建模启发了本项目的 `sentiment` 情感标注机制——不做二元的"喜欢/不喜欢"判断，而是保留用户态度的灰度（positive/skeptical）。
- **P5 (Geng et al., 2022)** — 将推荐视为生成式任务的范式，启发了本项目从"推荐什么新闻"到"这条新闻对你意味着什么"的 SCQA 生成式改写方案。
- **SCQA 框架** (Barbara Minto, *The Pyramid Principle*) — 麦肯锡金字塔原理的 Situation-Complication-Question-Answer 叙事结构，本项目首次将其应用于新闻个性化改写领域。
